# 全栈学习路线

每一课都要形成“代码能运行、能解释、能验证”的闭环，再进入下一课。

开始课程前先读 `00-ai-fullstack-essential-guide.md`。它不是要求你背完所有技术，而是帮你区分 AI 可以代劳的实现工作，以及开发者必须亲自理解和确认的业务、数据、安全、验证与发布责任。

## 1. HTTP 与前后端联调（已完成）

- React 页面调用 `GET /api/health`
- 理解 URL、请求、响应、JSON、状态码和开发代理
- 交付物：页面能显示后端状态和服务器时间

## 2. 数据库与正式评分（已完成）

- 使用 PostgreSQL 和 Prisma
- 学习表、主键、外键、迁移、增删改查
- 实现评审项查询与专家评分保存
- 交付物：服务重启后评分仍然存在

## 3. 参数校验与错误处理（已完成）

- 使用 DTO 校验请求参数
- 统一返回错误码和可读错误信息
- 交付物：非法分数无法写入数据库

## 4. 登录、鉴权与权限（已完成）

- 理解用户、Token、认证和授权
- 后端从身份信息确定专家，不能信任前端传入的专家 ID
- 逐文件慢速拆解见 `04b-auth-code-walkthrough.md`
- 交付物：未登录或无权限用户不能评分

## 5. 文件与对象存储（已完成）

- 第 5A 课（已完成）：multipart 上传、本地存储、数据库元数据和鉴权预览
- 第 5B 课（已完成）：接入 MinIO，将本地文件替换为对象存储
- 第 5C 课（已完成）：生成短期访问 URL，模拟正式投标文件预览
- 交付物：有权限的用户可限时预览文件

## 6. 自动化测试（已完成）

- 第 6A 课（已完成）：Vitest、Nest TestingModule 和后端单元测试
- 第 6B 课（已完成）：使用隔离的数据库与 MinIO 完成 API 集成测试
- 第 6C 课（已完成）：使用 jsdom 和 Testing Library 完成前端组件与关键交互测试
- 交付物：提交代码前可自动发现回归问题

## 7. Docker 化（已完成）

- 为前端、后端制作多阶段生产镜像
- 使用 Nginx 托管前端并反向代理 `/api`
- Docker Compose 编排前端、后端、数据库和 MinIO
- 理解镜像、容器、网络、健康检查、迁移和 Volume
- 交付物：新电脑一条命令运行完整系统

## 8. Nginx、域名与 HTTPS（已完成）

- Nginx 统一代理 API 与 MinIO 签名文件
- 当前：本地自签名 HTTPS、混合内容、CORS 和 iframe CSP
- 理解正式域名、CA 证书、开放端口与生产边界
- 交付物：通过统一 HTTPS 地址访问系统

## 9. CI/CD、生产部署、备份与回滚（已完成）

- 使用 GitHub Actions 自动检查、测试、构建并发布 GHCR 镜像
- 使用独立生产 Compose、不可变 SHA 镜像标签和人工发布关卡
- 备份 PostgreSQL 与 MinIO，生成 SHA-256 清单并验证归档
- 区分应用回滚与数据库恢复，形成不直接操作真实服务器的发布手册
- 交付物：代码合并后产生可重复部署、可验证、可回滚的版本

## 10. 可观测性与故障排查（下一课）

- 学习结构化日志、请求 ID、指标和告警
- 从“页面报错”沿 Nginx、API、数据库和 MinIO 定位问题
- 理解健康检查不等于业务可用，设计最小监控面板
- 交付物：出现故障时能发现、定位并留下可关联证据
