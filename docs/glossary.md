# 术语表

- **HTTP**：浏览器和服务器通信时共同遵守的规则。
- **API**：后端对外提供的功能入口，例如查询数据或保存评分。
- **JSON**：前后端常用的数据格式。
- **端口**：一台电脑上区分不同服务的编号，例如前端 5173、后端 3000。
- **开发代理**：开发时由 Vite 把 `/api` 请求转发给后端，页面不必写死后端地址。
- **数据库**：持久保存业务数据的系统，程序重启后数据仍存在。
- **ORM**：用 TypeScript 对象操作数据库的工具，本项目后续使用 Prisma。
- **Prisma Client**：根据数据库模型生成的 TypeScript 数据库操作代码。
- **迁移**：用可追踪的文件修改数据库表结构。
- **Controller**：接收 HTTP 请求并读取参数，不负责复杂业务规则。
- **Service**：处理业务规则，并调用数据库或其他服务。
- **依赖注入**：由框架创建并提供 Service，Controller 不需要自己实例化它。
- **DTO**：描述接口允许接收哪些字段以及字段类型的数据类。
- **ValidationPipe**：NestJS 在请求进入 Controller 前自动执行 DTO 校验的组件。
- **异常过滤器**：集中捕获异常，并把不同错误转换成统一响应格式的组件。
- **业务错误码**：程序用来区分失败原因的稳定标识，例如 `SCORE_OUT_OF_RANGE`。
- **认证**：确认调用者是谁，例如通过用户名和密码登录。
- **授权**：确认已经登录的用户是否有权执行某项操作。
- **JWT**：带签名的身份凭证，后端可验证内容是否被篡改以及是否过期。
- **Guard**：NestJS 在请求进入 Controller 前执行认证或权限检查的组件。
- **密码摘要**：通过单向算法得到的密码验证数据，数据库不保存用户的明文密码。
- **二进制文件**：由字节组成的数据，例如 PDF、图片和压缩包，不能当作普通 JSON 文本处理。
- **元数据**：描述其他数据的信息，例如文件名、大小、类型、上传者和上传时间。
- **multipart/form-data**：HTTP 上传文件时常用的请求体格式，可同时携带文件和普通字段。
- **FormData**：浏览器用于构造 multipart 请求的 JavaScript 对象。
- **MIME 类型**：描述内容格式的标识，例如 PDF 是 `application/pdf`。
- **文件签名**：文件开头用于识别真实格式的特征字节，也常称为魔数。
- **Blob**：浏览器内存中的二进制数据对象。
- **对象 URL**：浏览器使用 `URL.createObjectURL()` 为 Blob 创建的临时本地地址。
- **对象存储**：通过对象键保存和读取文件的服务，例如 MinIO 或云厂商 S3。
- **MinIO**：兼容 Amazon S3 协议的对象存储服务，本项目用它在本地学习文件存储。
- **Bucket（存储桶）**：对象存储中的顶层容器，类似一个专门存放对象的命名空间。
- **Object Key（对象键）**：对象在 Bucket 中的唯一名称，例如 `documents/2026/abc.pdf`；斜杠只是名称的一部分，不一定代表真实目录。
- **SDK**：供程序调用某项服务的代码库；本项目后端通过 MinIO SDK 上传、读取和删除对象。
- **Stream（流）**：分段读取和传递数据的方式，预览大文件时不必先把整个文件加载进后端内存。
- **存储端口（Storage Port）**：本项目定义的存储能力接口，使业务代码依赖“保存、读取、删除”能力，而不依赖本地磁盘或 MinIO 的具体写法。
- **Provider**：NestJS 依赖注入容器管理的对象；可以把同一个 Token 映射到不同实现。
- **预签名 URL**：对象存储根据密钥、对象键和过期时间生成的临时访问地址；使用者无需知道密钥。
- **TTL**：数据或凭证的有效时长，`300` 秒表示生成后 5 分钟失效。
- **查询参数**：URL 中 `?` 后面的键值，例如签名地址里的 `X-Amz-Expires=300`。
- **能力 URL**：任何拿到它的人都能在限定条件内执行某项操作的地址，因此签名 URL 应像临时密码一样保护。
- **自动化测试**：由程序执行操作和判断结果，可在每次修改后重复验证既有规则。
- **单元测试**：隔离外部系统，只验证一个函数、类或较小业务单元的行为。
- **集成测试**：让多个真实组件一起工作，例如 NestJS、PostgreSQL 和 MinIO，验证连接与协作是否正确。
- **端到端测试（E2E）**：从用户入口贯穿整个系统的测试，例如浏览器登录、上传并预览文件。
- **断言**：测试对结果提出的要求，例如 `expect(status).toBe(401)`。
- **Mock**：测试中代替真实依赖的可观察对象，可预设返回值并记录调用情况。
- **测试替身**：代替真实依赖的对象总称，Fake、Stub、Mock 都属于测试替身。
- **测试运行器**：发现、执行并汇总测试的工具，本项目使用 Vitest。
- **AAA**：Arrange、Act、Assert，即准备条件、执行行为、验证结果的测试结构。
- **Supertest**：不占用固定端口就能向 Node.js HTTP 应用发送测试请求的工具。
- **测试隔离**：让测试使用独立数据和资源，避免用例互相影响或污染开发、生产环境。
- **tmpfs**：将容器目录放在内存中的临时文件系统，容器销毁后测试数据自然消失。
- **装饰器元数据**：TypeScript 为类和参数生成的运行时类型信息，NestJS 用它识别 DTO 和依赖。
- **`prisma migrate deploy`**：按已有迁移文件更新数据库，适合测试和部署等非交互环境。
- **组件测试**：把一个 React 组件渲染到测试环境，通过页面元素和用户操作验证它的行为。
- **jsdom**：在 Node.js 中模拟浏览器 DOM 的库；它能创建元素和触发事件，但不是真正的浏览器引擎。
- **Testing Library**：鼓励从用户能看到和操作的内容出发测试页面的工具集合。
- **可访问查询**：按照角色、标签文字或可见文本查找元素，例如通过按钮名称查找按钮。
- **`screen`**：Testing Library 提供的全局页面查询入口，表示当前测试渲染出的文档。
- **`userEvent`**：用接近用户的方式执行点击、输入和文件选择等组合交互的工具。
- **jest-dom**：为 DOM 断言增加 `toBeDisabled`、`toHaveValue`、`toBeInTheDocument` 等易读匹配器的库。
- **`waitFor`**：反复执行断言，直到异步界面达到预期或超时；用于等待不能直接按文字查询的状态变化。
- **测试清理（cleanup）**：在每个组件测试结束后卸载 React 树并清空 DOM，防止用例互相污染。
- **环境变量**：放置不同环境配置的方式，例如端口和数据库地址。
- **构建**：把 TypeScript、React 等源码转换成可部署产物。
- **Nginx**：托管前端静态文件，并把 API 请求转发给后端。
- **Docker 镜像**：包含程序及运行环境的可复制软件包。
- **Docker 容器**：镜像实际运行起来的实例。
- **镜像层（Layer）**：Dockerfile 每个构建步骤形成的可缓存只读结果；输入不变时可以复用以加快构建。
- **构建上下文（Build Context）**：执行 Docker 构建时允许 Dockerfile 读取的文件集合，本项目使用仓库根目录作为上下文。
- **多阶段构建**：在同一个 Dockerfile 中先用完整工具链编译，再只把运行产物复制进更小的最终镜像。
- **`.dockerignore`**：从构建上下文排除依赖、密钥、构建产物和本地文件，减少传输并避免泄漏。
- **容器网络 DNS**：Compose 网络会把服务名解析为容器地址，因此 API 使用 `postgres:5432` 和 `minio:9000`。
- **反向代理**：由入口服务接收请求，再转发给内部服务；本项目 Nginx 将 `/api` 转给 NestJS。
- **健康检查（Healthcheck）**：容器内定期执行的探针，用于判断服务是否真正能响应，而不只看进程是否启动。
- **生产依赖**：程序运行时仍需要的依赖；TypeScript、测试框架等只在构建或开发阶段使用。
- **Volume**：Docker 管理的持久化空间，删除容器后数据库文件仍可保留。
- **CI/CD**：自动检查、构建和部署代码的流程。
- **日志**：程序运行时留下的事件记录，用于定位故障。
